# 原厂 Z8 检测头微调流程试验

[English](z8-finetune-probe.md) | **简体中文**

2026-10-25 已在本地 RTX 4080 Laptop GPU 上跑通“冻结原厂主干 → 原检测头短步数更新 → FP16 权重导出 → 完整原网络重新载入 → 原 Z8 后处理”的流程。输入为 3 张冻结的 384×256 图，更新 12 步。

## 已验证什么

- 原检测头有 8,784 个可训练的物理存储参数。本次实际改变 990 个浮点主参数，导出的模型副本改变 590 个字节；指令和非检测头字节保持一致。
- 更新前，训练侧重放和原厂冻结 heads 在 3 张图上逐位一致。
- 梯度有限且非零，正样本损失从 `0.05424943` 降到 `0.05402604`。
- 导出后重新执行完整网络，与训练侧 heads 在同样 3 张图上逐位一致；原 BA2 后处理返回码均为 0。
- 12 步后原始 heads 有变化，最终整数候选记录仍相同。这是流程验证，没有检测精度改善结论。

完整过程约 118 秒。PyTorch 张量峰值分配约 86 MiB，保留约 120 MiB；该读数不包括 CUDA 上下文和其他进程。主干被冻结，不能据此推算完整主干训练的显存。

## 如何解决不可直接训练的问题

推理封装使用 `inference_mode`，原算术还包含取整和整数位运算。原 dot 虽然可能显示 `requires_grad=True`，实测其权重梯度全部为零，不能据此认定能直接学习。

本试验不替换主干为普通浮点卷积。它缓存原网络实际送入检测头的特征；前向仍执行固定版本的原半精度算术，反向明确使用 STE 近似梯度。该结论只覆盖原检测头参数更新，尚未验证完整主干反向传播。

第一次预检查因缓存特征保留了推理张量属性而失败，未执行优化器更新。保留该失败记录后，在推理上下文之外复制为普通冻结张量，重新执行全部一致性检查后通过。

## 标注接入范围

当前正式纠错队列还没有人工确认记录；历史 30 条 AI 标注均可通过接口适配检查，共含 26 个头框、26 个无眼框的眼点。它们只用于工程流程测试，不作为已复核训练真值。

| 标注 | 本试验处理 |
|---|---|
| 头框 | 映射到原 slot 1，监督中心、宽高及正样本分数 |
| 只有眼中心 | 只监督 x/y，不制造眼框宽高，不强分 slot 2/3 |
| 边界明确的眼框 | 可保留几何；眼方向仍需另行确定 |
| 整鸟可见外接框 | 暂不自动当作 slot 0/4，原厂边界和子类未明确 |
| slot 5 辅助区域 | 保留原输出，暂不伪造训练目标 |
| 未标区域、未查看、疑似目标 | 不生成背景负样本 |
| 明确无鸟 | 本次正样本试验不使用；完整负样本损失需另行实现 |

两个标签格式均支持：历史 `forest-bird-input-manual-v1` 和新 `forest-bird-z8-correction-v1`。后者尚无鸟实例关联。没有关联不妨碍单独部位的检测损失测试，但无法完整评估“哪只鸟的眼、头和身”。原厂 anchor 内的几何字段由类别共享，未监督其他类别不等于这些类别的预测完全不受更新影响；正式微调仍需验证退化。

## 本地复现

代码不携带厂商权重、固件和 DLL。单独提供已验证的 E7 包、原 Z8 解包目录、标注工作区及冻结推理目录，输出必须在这些目录和公共仓库之外。

```powershell
python scripts/probe_z8_finetune.py `
  --upstream <E7-package> --z8-package <Z8-package> `
  --workspace <annotation-workspace> --frozen-runs <saved-Z8-runs> `
  --output <new-local-experiment-folder> `
  --ids fb_0008 fb_0012 fb_0018 --steps 12 --engineering-labels
```

`--engineering-labels` 显式允许未复核标签进行工程测试。去掉该参数时，未复核标签会被拒绝。脚本上限为 4 张图、20 步；任何一致性、梯度、导出或原后处理检查失败即退出，保留报告。模型副本留在本地，不能提交到公共仓库。

`probe_z8_multibird.py` 可用同类参数和 `--ids fb_0496 fb_0632` 分别执行原输入与水平镜像。镜像是受控诊断，不能计为新增独立照片。`pN` 是输出列表序号，不是鸟身份；具体部位看 slot 和图像位置。
