## 2. 总体做法：原片不动，编号稳定，标签可多选

接收目录维持投稿者原样；工作区未来生成校验副本和审核图。归类依据注册表与标签，不把同一照片不断挪入“虚焦/遮挡/某鸟种”目录。

同一图可能同时具有“细枝穿眼、失焦、小目标、多鸟”等属性，因此不强迫落入一个互斥文件夹。物理存放解决资产管理，标签解决选图和统计。

## 3. 编号规则

### 3.1 沿用 DS 编号

永久资产 ID 为 `fb_0001`、`fb_0002`……数字至少四位。已有 `fb_0001`～`fb_0292` 的 ID 和原文件哈希对应关系保持不变；新增资产从**实际注册表最大已用号**之后追加。

ID 不编码鸟种、摄影者、日期、焦点是否正确、train/test 或标注结果。这些信息会修订，ID 必须稳定。不得因为新增文件排在旧文件前面就整体重编号。

本次发现 4 个新文件；若执行登记时仍只有这 4 个新增资产且未被其他登记占号，才追加为 `fb_0293`～`fb_0296`。本轮不预占或分配。

### 3.2 资产、曝光和场景分开

| ID / 字段 | 表示什么 | 规则 |
|---|---|---|
| `image_id` | 一个来源图像字节资产 | `fb_0001`；原始字节哈希固定 |
| `source_occurrence_id` | 某次接收/投稿记录 | 同一资产可多次被投稿，分别留来源 |
| `photographer_id` | 经核实的摄影者代号 | 如 `p_0001`；未确认用 null，不从文件夹或序列号臆测 |
| `submission_id` | 投稿交付批次 | 如 `sub_20261024_001`；一次投稿可含多个拍摄日期 |
| `capture_id` | 同一曝光 | RAW、机内 JPEG 或编辑版可关联；未确认用 null |
| `sequence_id` | 同一连拍或连续拍摄 | 相邻、近似曝光整体关联，不等于物种文件夹 |
| `scene_id` | 同一拍摄场景或重复背景 | 同场景跨时段是否合并需审核 |
| `duplicate_group_id` | 像素近重复/派生家族 | 感知相似是候选线索，人工确认关系 |
| `leakage_group_id` | 不能跨训练/测试的关联组 | 合并上述有依据的关系形成关联分量 |
| `instance_id` | 一张图里的某只鸟 | 如 `b1`、`b2`，只在该 image_id 内唯一 |

JPEG 和 RAW 若为不同字节资产分别编号，但可共享 `capture_id`。同图重新压缩、裁切、社交平台导出也单独记录字节资产和 `parent_asset_id`；不能因此分到两个数据划分。

审核图是同一资产的派生表示，沿用 image_id，通过 `render_id` 和审核图 SHA-256 区分，不再创建新的社区资产编号。图内多个鸟不拆成多个原图 ID。

### 3.3 后续增量登记的顺序

1. 枚举接收文件，保留来源路径；文件还在写入时跳过并列入待重试。
2. 读取原始文件 SHA-256，核对旧注册表。完全相同的资产追加来源记录，不发新主 ID，不删除投稿文件。
3. 未见过的哈希由单一登记进程分配递增 ID。更新注册表、映射和快照要原子提交，失败不能留下半条记录。
4. 如需标准编号副本，复制后重新验哈希；保留原始扩展名所代表的格式，不把 NEF 改扩展名假装 JPEG。
5. 渲染审核图并记录其独立哈希、尺寸和参数。解码失败进入 `decode_failed`，不得悄悄少图。
6. 人工建立同曝光、连拍和近重复关系，补标签；状态未知可留空。
7. 输出成功/重复/失败/待确认清单。本轮只定义流程，不执行上述登记写入。

## 4. 归类字段

### 4.1 归类的六个维度

| 维度 | 推荐字段/值 | 使用方式 |
|---|---|---|
| 来源与资产 | 摄影者、投稿批次、原片/导出/平台版、来源可信度 | 不能用“没有 EXIF”自动判定截图或非法来源 |
| 场景与个体 | 物种线索、场景、连拍、鸟个体数 | 物种可未知，不阻挡部位标注 |
| 遮挡 | `none/branch/leaf/dense_foliage/trunk/grass/other_bird/other/unknown` | 多选，并分别标被挡部位 |
| 图像质量 | `defocus/motion_blur/compression/underexposure/backlight/none/unknown` | 多选；模糊与遮挡分开 |
| 可辨目标 | `eye/head/body/none/unknown` | 先按原图证据，模型输入上的结果另记 |
| 工作状态 | 接收、来源核验、解码、待标、初标、复核、授权、划分 | 每种状态独立，不能用一个“已完成”掩盖缺项 |

`target_size` 保存实际框尺寸和面积占比；“小/中/大”只作为特定评测协议生成的派生分层。未固定输入预处理前不随意套用小目标阈值。

### 4.2 兼容旧 A/B/C 分组

旧 `group_abc` 保留为粗筛字段，不主导存储，也不是全部训练标签：

- A：有鸟且存在遮挡。文件名中的“失败”只是投稿者判断；是否真的识别失败需后续比较。
- B：正常对照，可有复杂背景、小鸟和不同姿态。
- C：有鸟但证据不足/无可用部位，或疑似鸟无法确认；内部必须再分“确认鸟/不确定区域”。
- 新增 D：经人工检查的无鸟难负例，例如枝叶纹理。

同一图可有多只不同状态的鸟，因此最终以实例字段为准。C 不能直接转换成“无鸟”，D 不能由某个模型漏检来决定。

现有“单点”“虚的”和鸟种目录只存 `source_hint`；未知摄影者不按这些目录自动编造身份。无 EXIF、平台压缩版和来源待确认图片暂入审核队列，合规且内容可辨时仍可使用，并单独报告分布。

## 5. 审核图与坐标规范

### 5.1 固定一份用于标注的图像表示

人工查看原始照片内容，但所有几何坐标绑定到**冻结的审核图**：

- JPEG/PNG 应用 EXIF 方向后固定实际显示宽高；保存原资产哈希和审核图哈希。
- NEF 选定统一 RAW 渲染配置后生成全尺寸审核图；记录解码器版本、白平衡、颜色空间、可见裁切和导出设置。嵌入预览与正式 RAW 渲染不得混称同一种输入。
- 如果要保留机内直出与 RAW 渲染比较，两者分别记录来源表示，通过同曝光关系绑定。
- 不使用超分、去遮挡生成、AI 锐化或生成眼睛作为真值证据；普通放大仅帮助查看已有像素。
- 不在浏览器缩略图坐标上直接提交结果，不把 RAW 传感器尺寸硬套到渲染图。

坐标均为审核图上的原像素：`[xmin,ymin,xmax,ymax]`，零起点、右下不包含，允许浮点。点为 `[x,y]`。必须满足框宽高大于零、边界合法；EXIF 方向/裁切改变后须转换坐标并生成新版本，不能只改 width/height。

### 5.2 框和点的定义

| 标注 | 必填条件 | 具体边界 |
|---|---|---|
| `bird_bbox_xyxy` | 可确认为鸟且能定位可见范围 | 包住该鸟所有可见片段，含头、翅、尾和足；不是仅躯干框 |
| `head_bbox_xyxy` | 有证据可定位头部 | 可见头部与喙；头完全不可辨用 null |
| `eyes[].center_xy` | 实际可定位眼 | 每只可见眼一个中心点；隐藏眼不记录假坐标 |
| `eyes[].bbox_xyxy` | 眼边界确实可辨 | 不强制所有眼都有框，不扩成固定 5×5 或 10×10 假框 |
| `af_anchor_original_xy` | 参考目标为 eye/head/body 时 | 在所选可见部位上的参考点；不能机械取框中心落到枝叶上 |
| `uncertain_regions` | 不能确认是否为鸟 | 疑似范围和原因，供复核；不视为负例 |

整鸟可见框是所有可见片段的外接矩形，矩形内部可能有枝叶或空隙。**框内不保证每个像素都属于鸟**，因此不能仅以预测点落在整鸟框内就判定对焦正确。第一版记录可见参考点和人工锁点复核；需要自动评估可见区域时再增加独立的可见区域掩码规范，不在本轮强制逐像素分割。

`body` 是“退到整鸟目标”的简写，训练类别 `bird` 表示整鸟，不额外引入含义模糊的仅躯干类别。

## 6. 人工标注的顺序

1. 看整张图，记录能确定的鸟数和疑似区域；不要先看任何待比较模型的预测。
2. 逐鸟画可见整鸟框，并分配 `b1/b2/...`。首次按由左至右、由上至下排序方便协作；之后修框不重排已有实例 ID。
3. 能辨认头则画可见头框；看得到的眼分别点中心，有可靠边界再画眼框。
4. 按眼、头、整鸟分别记录可见性；记录遮挡物、被挡部位和不能定位的原因。
5. 给出原图参考层级，标记可见部位上的参考点；无法确定则 unknown 并提交复核。
6. 保存初标记录，复核者独立检查漏鸟、隐藏眼、误负例、框边界和实例关联。

暂不要求物种、翅膀框、尾巴框、脚框、每片树叶或全部树枝的框。被遮挡尾部等可以记录属性，不扩大为大量新类别。

### 原图参考层级

| 值 | 判据 |
|---|---|
| `eye` | 至少一只眼在审核图上有可靠可见证据并可定位 |
| `head` | 眼不可可靠定位，但头可定位 |
| `body` | 眼和头均不可可靠定位，但整鸟可见部分可定位 |
| `none` | 已确认存在鸟，但没有可用部位参考；或整张图确认无鸟（须由 presence 区分） |
| `unknown` | 连是否为鸟或可用部位都不能确定，保留疑似区域 |

背向、遮挡、失焦、运动模糊、压缩、太小和出画分开记录。不要把“看不见眼”一律归因于树叶。

### 模型输入上的可用性另行评估

原图标注一次，各模型各自保存 `input_assessments`。每条记录必须引用固定 `preprocess_id`，包含 resize/letterbox/ROI、颜色和坐标变换定义，并记录输出尺寸和版本。

例如 Z8 研究输入为 384×256，但**只有尺寸不足以定义真实预处理**。在流程未核实前，`input_assessments=[]`，不能先任意拉伸图片再把眼改成不可见。模型输入太小导致眼消失，与原图中被树枝遮住，是不同问题。

同一目标在原图可锁眼、在某输入上只能锁头是合法结果，两条记录都保留。原图 `none` 不等于应训练检测器输出“无鸟”；训练损失中的正样本、忽略区和负例规则应在后续训练适配器另行定义。

## 7. 主标注记录与旧格式兼容

新规范 `schema_version="forest-bird-manual-v1"`，每张审核图一条 JSONL：

| 字段 | 类型/约束 |
|---|---|
| `image_id` | 已登记社区 ID；例子不能当作真实标注 |
| `review_image` | `render_id`、`sha256`、`width`、`height`、`orientation_applied` |
| `annotation_status` | `pending/annotated/reviewed/needs_adjudication` |
| `presence` | `present/absent/uncertain/null`；pending 时为 null |
| `instances` | null 表示未标；数组表示完成初步检查后的确定实例 |
| `uncertain_regions` | null 表示未检查；已检查后为空或疑似区域数组 |
| `input_assessments` | 初版默认空；后续按固定输入流程单独记录 |
| `provenance` | 匿名标注者/复核者 ID、UTC 时间、协议版本、修订号和父版本 |
| `split` | 当前 null；未来由 split manifest 引用，不随标注者任意修改 |

实例字段：`instance_id`、上述框和眼数组、`part_visibility`、`invisibility_reasons`、`occluder_types`、`occluded_parts`、`af_reference_target_original`、`af_anchor_original_xy`、`needs_review`、`notes`。

`part_visibility` 的 bird/head/eye 分别取 `visible/partial/hidden/out_of_frame/unknown`。无鸟不存在鸟实例，不生成三个 hidden 的假实例。`invisibility_reasons` 可含 `occlusion/pose/defocus/motion_blur/too_small/compression/out_of_frame/unknown`；原因不确定不猜。

眼数组元素使用 `eye_id`、`center_xy`、`bbox_xyxy` 和 `side`。`side` 按鸟自身左右记，不能确定用 unknown，不以画面左右代替。两只眼必须属于同一实例。

不确定区域使用 `bbox_xyxy`、`reason` 和 `needs_review=true`。同一图片有确定鸟和疑似区域时可同时存在，不能要求整图只选一种情况。

### 三种关键空值

| 内容 | 含义 | 能否直接当负样本 |
|---|---|---|
| pending，instances=null | 没标 | 不能 |
| reviewed，presence=absent，instances=[]，uncertain_regions=[] | 人工确认无鸟 | 可作为负样本候选，仍需来源与划分检查 |
| presence=uncertain，instances=[]，uncertain_regions 非空 | 有疑似目标 | 不能 |

DS 已有 292 行空模板中的 `instances=[]` **全部是未标**，不具有上述“已检查为空”的含义。迁移后显式写 pending，不自行判断为无鸟。旧 `bird_box/head_box` 是 xywh，转换时需核对绑定的图像尺寸与方向；不能仅把字段改名为 xyxy。旧单眼 `eye` 和 CUB 的 `birds/eyes` 同样需要有版本的映射，不静默互换。

旧 manifest 的曝光、格式和物种提示也需验证。例如零秒快门、MPO 解码行为、NEF 可见尺寸都不能直接当作正确标签。没有 EXIF 不自动证明截图。

## 8. 标注工具和首批执行安排

**当前 AI 初标补充（2026-10-24）**：既有本地工具已部署，AI 初标执行 [流程 v2](../overview/ai-annotation-workflow-v2.zh-CN.md)，输入 schema 为 `forest-bird-input-manual-v1`。先 5 张新图验证叠框自检，既有整个批次人工全检，首批 40 张校准后再扩量。AI 不读取 Z8 预测或原图推断输入标签。下文 CVAT 及双人初标为历史设计；只有一名人工时如实记录 AI 初标加人工复核，不宣称独立双人。原图标注结构不因此改版。

推荐将来使用**本地 CVAT** 做人工协作，原因是支持矩形、点、属性和形状分组；这只是工具选择，当前不安装或启动服务。官方参考：[标注形状](https://docs.cvat.ai/docs/annotation/manual-annotation/shapes/)、[CVAT 原生图像格式](https://docs.cvat.ai/docs/dataset_management/formats/format-cvat/)。

计划的工具标签：

- `bird`：矩形，携带实例属性。
- `head`：矩形，与所属鸟共用组号。
- `eye_center`：点；`eye_box`：可选矩形，附眼 ID。
- `af_anchor`：点，与所属鸟共用组号。
- `uncertain_region`：矩形，不混进确定鸟组。

工具组号通常只在任务内有效，导出时用“任务/图片/组号 → image_id/instance_id”映射。保留原生导出和项目 JSONL；纯 YOLO 检测 txt 不能单独承载眼中心、实例关联、unknown、复核和授权信息，因此只能作为未来训练的派生格式。

首批建议选 40 张独立样本，覆盖 10 张清晰/小鸟、10 张眼部遮挡、8 张头部遮挡/仅露身体、6 张疑似鸟/无鸟背景、6 张模糊/平台压缩/多鸟。若某类不足，记录实际数量，不凑数、不凭空造负例；同一连拍最多选少量代表帧以避免 40 张都是同一场景。

两人独立初标后裁决分歧，形成图示手册再扩量。先不让 Sony、Z8 或其他模型生成该批真值。没有第二位标注者时按分时段自复核执行，并注明非独立复核。

后续待授权执行时，任务包目标 50 张左右；连拍/场景整体交给同一任务或保持映射，不为凑满任务拆散泄漏组。统计初标和复核耗时后再估算全量成本，不预设每张图几秒就能完成。

## 9. 质量检查

### 自动检查（未来实现，不宣称已有脚本）

- ID 唯一、原片/审核图哈希存在，图像宽高和方向匹配。
- 所有框坐标合法，眼中心在相应眼框内；头/眼实例关联完整。层级包含异常提交人工检查，不能自动扩大整鸟框掩盖问题。
- target=eye 时存在可定位眼；target=head/body 时存在相应框及有效参考点。target=none/unknown 时参考点为空。
- pending 不导出训练，presence=absent 不含鸟实例；疑似区域不自动当负例。
- reviewed 要有复核者和修订记录；初标不能伪装成审核完成。
- 同一 leakage_group 不跨 split；同曝光/派生链不能跨 train/test。

### 人工检查

测试候选、严重遮挡、多鸟、无鸟/应放弃、全部不确定项 100% 复核；其余训练候选每批随机抽检至少 20%。隐藏眼、实例错配、漏鸟、疑似鸟误作负例和跨划分泄漏属于关键错误，发现即退回该批修正。

眼点误差按审核图像素与固定模型输入像素分别报告；头/鸟框分歧、层级分歧和实例数分歧分别统计。首批校准后再冻结数值容差，不能任意用一个 IoU 阈值覆盖小鸟和眼点的全部质量问题。

## 10. 数据划分和后续效果对比

当前 split 全部未分配。先完成重复/序列关系和标注，再考虑按组分层的 70/15/15 起始比例；296 个文件不是 296 个独立拍摄场景，不能现在直接随机抽 15% 当测试。

划分依据 `leakage_group_id` 的关联分量，覆盖连拍、同曝光不同格式、裁切重编码和合成派生图。未知关系先待核验，不以“摄影者不知道”作为允许逐图随机切分的理由。可另外保留整位已确认摄影者的域外测试组，但不是当前收集阶段的强制前提。

测试集在模型选择、教师比较和调阈值前冻结，保留分组及 SHA-256。后续优化以同图配对比较，报告真实遮挡正确锁定、眼/头/鸟召回、错误回退、误锁枝叶、清晰小鸟退化和同口径运行时间。必要时按场景组统计不确定性，不能让某一段大量连拍主导结论。

头/鸟框包含枝叶，不能把“框里有点”直接计为实际合焦；离线结果与相机镜头闭环合焦另行验证。本轮不跑模型对比，也不指定教师、启动训练或部署权重。

## 11. 公共仓库和隐私

公共 Git 仓库保存规范、代码、脱敏清单和取得许可的标注；正式照片包未来按许可通过 Releases 发布。项目原创文档许可不自动覆盖摄影者照片。

授权逐资产记录为 pending、internal_only、public_cc_by_4_0 或 restricted；public_cc_by_4_0 必须是作者明确理解商用和再分发后选择。公开署名单独征询；编号或去 EXIF 不保证完全匿名。

私人注册表保存原路径、精确时间/位置、机身序列号和授权原文；公共清单使用必要字段的白名单，通常保留 ID、尺寸、哈希、相机型号、粗粒度场景、审核状态和许可。

**现有公开 manifest 含机身序列号。** 应在后续公开资料维护中去标识化；这里只记录待修订项，不默默重写 DS 历史提交，也不声称当前 Git 历史已清除。无 EXIF 的图片需核查来源，但不应仅因缺 EXIF 就排除使用。
