# Sony `.nab` 网络资产包格式

本文记录从 Sony a1 II 固件 v4.00 的 `default.nab` 逆向出的容器格式。

**核心原则：本仓库公开格式知识与验证方法，不公开权重本体。**

---

## 0. 证据等级说明

本文每个结论都标注证据级别，请按级别采信。

| 级别 | 含义 |
|---|---|
| **A 实测确认** | 在真实文件上逐字节验证，多重交叉核对一致 |
| **B 结构自洽** | 字段值与已知结构逻辑吻合，但无独立参照物 |
| **C 推测** | 有线索但未验证，不可当作事实使用 |

**未标注的部分默认为 C 级，请不要自行假定。**

---

## 1. 整体布局

`default.nab` 是一个容器，内含多个独立网络。文件结构：

```
┌─────────────────────────────────┐ 0x000
│ 文件头 (0x00 - 0x50)             │
├─────────────────────────────────┤
│ 槽位表 (0x110 起，stride 0x30)   │
├─────────────────────────────────┤
│ 网络 0: VPMN 描述符 + 层 + 权重   │
├─────────────────────────────────┤
│ 网络 1: ...                      │
├─────────────────────────────────┤
│ ...                              │
├─────────────────────────────────┤
│ 网络 16: ...                     │
└─────────────────────────────────┘ EOF
```

网络之间**首尾相接、互不重叠**。每个网络的起始位置由 `VPMN` 魔数标记。

实测：17 个网络合计 40,046,464 B，源文件 40,047,760 B，差 1,296 B 为文件头与槽位表。**[A]**

---

## 2. 文件头

偏移 0x00 起，小端序：

| 偏移 | 类型 | 实测值 | 说明 | 级别 |
|---|---|---|---|---|
| 0x00 | char[2] | `"NA"` | 魔数 | A |
| 0x02 | u16 | 0 | 对齐 | A |
| 0x04 | u32 | 78 | 版本号 | A |
| 0x08 | u32 | 1 | 未知，恒为 1 | A |
| 0x0C | u32 | 17 | **网络数量** | **A** |
| 0x10 | u32 | 48 | 未知 | A |
| 0x14 | u32 | 128 | 未知 | A |
| 0x18 | u32 | 176 | 未知 | A |
| 0x1C | u32 | 32 | 未知，可能是记录大小 | A |
| 0x20 | u32 | 720 | 未知 | A |
| 0x24 | u32 | 32 | 同上 | A |
| 0x28 | u32 | 1264 | 未知 | A |
| 0x2C | u32 | 0 | 保留 | A |

`0x0C` 处的网络数量与实际扫描到的 VPMN 数量一致，可用来校验解析完整性。**[A]**

## 3. 槽位表

起始 0x110，步长 **0x30**。

```c
struct Slot {
    uint32 slot_id;      // 槽位编号
    uint32 buf_size;     // 缓冲区字节数
    uint32 offset_a;     // 缓冲偏移 A
    uint32 offset_b;     // 缓冲偏移 B
    uint32 marker;       // 恒为 32
    uint32 pad[7];       // 全零
};
```

实测 14 条有效记录（slot 4,5,6,7,8,9,10,11,14,15,16,17,18,19），编号不连续。**[A]**

### 关键验证：`buf_size` 与输入尺寸

`buf_size` 与网络输入张量的 `H × W × C` 精确对应，这是确认解析正确的关键证据。**[A]**

| slot | buf_size | 分解 | 对应网络 |
|---|---|---|---|
| 4 | 150,528 | 224 × 224 × 3 | net[3] 输入 |
| 5, 6 | 230,400 | 480 × 480 × 1 | 中间缓冲 |
| 7 | 49,152 | 128 × 128 × 3 | net[6] 输入 |
| 8, 9, 10, 11, 16, 17 | 307,200 | 320 × 320 × 3 | 部位检测器输入 |
| 14 | 6,144 | 32 × 64 × 3 | net[11] 输入 |
| 15 | 12,288 | 64 × 64 × 3 | net[12] 输入 |
| 18, 19 | 359,424 | 416 × 288 × 3 | head 检测器输入 |

**注意**：`offset_a` 与 `offset_b` 指向的是**画布/缓冲区**，不是网络描述符。早期把 `offset_b` 当作网络索引是错的，已在文档中纠正。**[A]**

## 4. 网络描述符 VPMN

每个网络以此开头。

```c
struct Vpmn {
    char     magic[4];     // "VPMN"
    uint16_t version;      // 0x0D / 0x0F / 0x16 三档
    uint16_t flag;         // 恒为 1
    uint32_t name_len;     // 实测 0xD4 = 212
    char     name[212];    // NUL 填充
};
```

`version` 有三档，与打包器代次相关。实测：**[A]**

| version | 使用网络 | 特征 |
|---|---|---|
| 0x0D | net 0, 1, 2, 5 | 早期 |
| 0x0F | net 3, 4, 6, 7-14 | 主流 |
| 0x16 | net 15, 16 | 最新 |

`name` 字段中，部分网络名为 `dummy_network_name`（6 个），说明**打包时名字被刻意剥离**。这不是解析错误。**[A]**

---

## 5. 张量描述符

用于声明输入、输出与中间张量。记录长度 0x64 字节，名字位于 **+0x34**。

```c
struct Tensor {
    uint32_t marker;      // 恒为 4
    uint32_t H;
    uint32_t W;
    uint32_t C;
    uint32_t one0;        // 恒为 1
    uint32_t one1;        // 恒为 1
    uint32_t one2;        // 恒为 1
    uint32_t dtype;       // 实测为 2
    uint32_t zero;        // 恒为 0
    uint32_t two;         // 恒为 2
    int32_t  fixed_pos;   // 原记为 zero_point，见下方警告
    float    scale;       // 量化缩放
    uint32_t name_len;
    char     name[];      // "input[0]" / "uid_NNN_out_0" / "output[K]"
};
```

### ⚠️ 重要修正：`+0x28` 不是 zero_point

早期报告写的是 `zero_point = -127`，**这个判断需要撤回**。

后续用 VeriSilicon 官方 NBG 解析器（TIM-VX，提交 `702715d7`）验证时发现：
- 该值是 `fixed_pos` 字段
- 在 non-symmetric quantization 配置下，真正的 zero_point 是 **128**
- `-127` 无法作为 INT8 零点使用

详见 [`docs/reports/03-pilot-run-002.md`](../reports/03-pilot-run-002.md)。**[A]**

### 已确认的 scale 值

| scale | 含义 | 使用的网络 |
|---|---|---|
| 0.0039215689 | 1/255 | net 0,1,3,11,12,15,16 |
| 0.0078431377 | 2/255 | net 6,7,8,9,10,13,14 |
| 0.018477604 | — | net 4,5 |

**注意这里有个差异容易踩坑**：部位检测器（net 8/10/14）与头部检测器（net 15/16）的输入 scale 不同，前者 2/255、后者 1/255。复原预处理时必须分开处理，否则数值差一倍。**[A]**

## 6. 层记录

层记录声明每层的输入来源与算子类型。**变长**，非固定步长。

```c
struct Layer {
    char     input_name[0x40];  // 输入张量名
    uint32_t marker;            // 恒为 1
    uint32_t layer_index;
    char     type[0x40];        // 算子类型名
};
```

### 已观察到的算子类型

| 类型名 | 出现次数（net 7） | 说明 |
|---|---|---|
| `ConvolutionReluPoolingLayer2` | 61 | 卷积+ReLU+池化融合 |
| `PoolingLayer2` | 3 | 独立池化 |
| `ActivationLayer` | 6 | 激活 |
| `ConvolutionReluPoolingLayer` | — | 变体 |
| `ConvolutionLayer` | — | 纯卷积 |
| `ConcatLayer` | — | 拼接 |
| `BatchNormalizationLayer` | — | BN |
| `Softmax2Layer` | — | Softmax |
| `FullyConnectedReluLayer` | — | 全连接+ReLU |
| `DeConvolutionLayer` | — | 反卷积 |
| `L2NormalizeLayer` | — | L2 归一化 |
| `NormalizeLayer` | — | 归一化 |

**层记录的精确边界尚未完全确定。** 目前用类型字符串回溯 `0x48` 定位记录起点，在实测样本上正确，但未在所有层类型上交叉验证。**[B]**

### 层表

网络描述符之后存在一张层偏移表，实测结构：

```c
uint32_t layer_table_count;   // 实测 64（不等于实际层数）
uint32_t data_size;           // 实测 2688 = 64 × 42
// 随后是 count 个 u32 偏移，指向网络内的层/张量记录
```

**注意**：`layer_table_count` 是表容量，不等于实际层数。实际层数需遍历层链或统计类型字符串。例如 net[0] 表容量 64，实际 152 层。**[A]**

## 8. 如何验证你的提取是正确的

不提供权重，但提供**可验证的中间结果**，你可以自行从官方固件复现并比对：

### 校验点 1：网络数量

文件头 `0x0C` 应为 17，与扫描到的 VPMN 数量一致。

### 校验点 2：网络边界

每个网络的起止偏移：
```
net[0] 0x00000510 .. 0x001329B0
net[1] 0x001329B0 .. 0x00152210
...
net[16] 0x02483290 .. 0x02631490
```
相邻网络的 end 必须等于下一个的 start，末网络 end 必须等于文件大小。

### 校验点 3：buf_size 对应

槽位表的 `buf_size` 必须能被分解为某个网络输入的 `H×W×C`。见第 3 节表格。

### 校验点 4：网络结构

每个网络的输入输出形状、层类型统计，见
[`docs/reports/01-a1ii-v400-unpack.md`](../reports/01-a1ii-v400-unpack.md) 第 5 节完整清单。

三项全对，说明你的解包与解析是正确的。
