# 鸟类眼—头—身检测：三组对比与蒸馏方案 v1

日期：2026-10-23。状态：方案草案，未执行。当前仅查阅本地模型与官方资料，未下载权重/数据、未运行教师、未训练、未修改固件。下述数量、超参数和通过条件均为拟定值，不是实验结果。

## 1. 明确决策

**教师选 YOLO26m 检测版，以 `yolo26m.pt` 初始化，微调为 `bird_body / bird_head / bird_eye` 三类鸟部位检测器。学生分别为原生 744 固定结构和 YOLO26n。原生 744 原权重作为冻结基线。**

第一版统一用检测框表达三个部位，眼框中心作为锁眼位置；保留左右眼中心、可见性和个体归属作为标注及评测字段。不额外部署关键点网络，不把原生人眼模型 710 套到鸟眼上。

教师需要先训练成鸟部位模型。通用 COCO 检测权重可以初始化网络，但不能直接提供鸟头、鸟眼监督；COCO pose 的人体关键点权重也不是现成鸟眼教师。YOLO26 的 detection / pose 是不同任务模型。[官方模型说明](https://docs.ultralytics.com/models/yolo26)、[官方 pose 说明](https://docs.ultralytics.com/tasks/pose)

## 2. 三个主组

| 组 | 网络与初始化 | 训练 | 输出与比较用途 |
|---|---|---|---|
| A：原模型不动 | 744 原权重、原结构、原 IPU 后处理保持冻结 | 不训练 | 现有方案的识别基线；另外建立经数值核对的张量实现供公平计时 |
| B：原架构蒸馏 | 相同 744 结构，原权重初始化 | 人工 GT + 同一冻结教师的离线监督 | 验证在原成本附近能提高多少；保留输入、通道、anchor、六类输出槽和布局 |
| C：YOLO26n 蒸馏 | `yolo26n.pt` 初始化，检测头改为三个任务类 | 与 B 相同人工 GT 和教师监督 | 与 B 比较精度—成本；首版保留标准 n 结构，不另加 P2/注意力/ROI 二级网络 |

三组主评测均输入 **384×256**，采用同一完整画面的几何变换。A 的部署参考仍为包中既有 RGB、bilinear resize、CHW 约定；三组主榜跟随相同变换，不能只给 C 更大的输入。教师可以看 **768×512** 原图适配画面，坐标映射回共同输入平面；不把高分辨率教师结果视为学生必然可见的信息。

A 原 PCNNP 的 SHA-256：`c5b564ff0c08f876b717649cacdd22ae5e997e0b1239fd99f9e7300531193f72`。位置 MAIN `0x21b0000`，原包 1,543,904 B，逻辑参数含偏置 661,943，逻辑 MAC 300,426,240。输出为 24×16×22 与 12×8×33。数据来自本轮之前已核对的本地预算证据。

**六个原生类别的完整语义/姿态分支映射需要先确认。** 包中可以确认类数、类号传输和 `+6` 主机类号转换，但界面仍显示原厂类号，不能凭六个槽自行填入标签。先通过原后处理消费者和人工标注样本建立 `native_class → body/head/eye (+姿态属性)` 映射。若有方向或姿态子类，必须保留并补充对应标签；不能简单把六类改成三类再称为“原架构完全不变”。未确认映射时，B 的正式训练和 A/B/C 的部位精度结论均不成立。

三主组足以比较最终方案，但不能把 B−A 全部归因于蒸馏：数据微调本身也可能有收益。如需回答“蒸馏比普通微调好多少”，在主结果后增加 B 的同预算 `KD=0` 消融，不改变用户要求的三条主线。

## 3. 教师选择及使用

选择 YOLO26m 的理由是：容量明显高于两种学生，沿用检测任务和同一标签定义，便于产生统一框与分数监督；在本地 4080 Laptop 12 GB 上可从较小微批次尝试微调，再离线推理。是否装得下具体配置必须由后续短测决定，不预报显存峰值、耗时或任务准确率。

官方公布的 COCO 融合推理结构约为 20.4 M 参数、68.4 GFLOPs@640；这些数值仅用于教师容量的数量级定位，不代表改成三类后的实际计数或鸟眼性能。[YOLO26 官方表](https://docs.ultralytics.com/models/yolo26)

初版先下载 `yolo26m.pt`、`yolo26n.pt`，保存 release URL、包版本、源码提交和 SHA-256。m 先用人工标注训练；教师在固定验证集达到部位定位与错误锁眼要求后冻结，随后给 B/C 生成完全相同的教师缓存。没有验证出可靠鸟眼教师时，不因其参数更多就开始蒸馏，也不自动升级到 x 或换教师。

默认采用 **离线输出蒸馏**，不缓存全网络特征、不让教师常驻学生训练显存。教师缓存只来自训练 split，记录图像哈希、教师权重哈希、几何变换、类别、框、置信度和有效/忽略状态。教师不进入最终推理链。

## 4. 数据集选择与下载清单

### 4.1 第一批必须下载：CUB-200-2011 原始包

- 官方共 11,788 张、200 个鸟种，每图有身体框和 15 个部位位置；适合建立身体/头/眼的监督与可见性检查。
- 下载完整 `CUB_200_2011.tgz`，不要只有分类图片的裁剪版。需要 `images.txt`、`train_test_split.txt`、`bounding_boxes.txt`、`parts/parts.txt`、`parts/part_locs.txt`，保留原 README。
- 官方存档显示约 1.2 GB（项目页写 1.1 GB），MD5 `97eceeb196236b17998738112f37df78`。下载后同时计算 SHA-256 并核对条目、可解码性和标注坐标。
- 需要头部/眼部实际范围时补标；现有 part 是点，不能冒充真实眼框/头框。

来源：[项目页](https://www.vision.caltech.edu/datasets/cub_200_2011/)、[官方存档及文件](https://data.caltech.edu/records/65de6-vp158)。项目页提示与 ImageNet 可能有图像重叠，因此不能称其测试集从未被任何预训练网络见过。保存官方 split，学生/任务教师的训练、验证只从官方 train 池抽取，官方 test 保留为测试池。

### 4.2 第一批必须下载：COCO 2017 实例标注及定向图像

- 先下载 `annotations_trainval2017.zip`，读取 `instances_train2017.json / instances_val2017.json`。
- 根据标注筛选鸟图，以及无鸟的难负样本，只取所需原图。COCO 中鸟类原始 category ID 与框架连续索引须从 categories 表匹配，不能把两种 ID 混用。
- 鸟图补充自然场景、小目标和多目标；负样本选择树枝/叶片、动物脸、天空/水面、复杂建筑等。标注表“没有 bird”不自动等于真实无鸟，抽查后才可作负例。
- 有鸟图只有身体标注，必须补齐所有可锁头、眼及其他鸟个体，才能进入首版三类训练。否则标准检测损失会把未标注眼/头当背景。
- 首版不依赖部分标签掩码的新实现。未补齐的图先留在原始池，不送入默认训练器；后续若做部分监督，须显式实现并验证 ignore mask。

来源：[COCO 官方入口](https://cocodataset.org/#download)、[官方项目配置中的下载项](https://raw.githubusercontent.com/ultralytics/ultralytics/main/ultralytics/cfg/datasets/coco.yaml)。不要求下载整套约 20 GB 图片，实际定向子集大小在筛选后统计。

### 4.3 第二批扩展：NABirds

NABirds 论文报告 48,562 张图，身体框和 11 个部位的位置/可见性，适合扩展不同鸟种与姿态。第一版先完成 CUB+COCO 的标注和对比，不用 48k 的规模掩盖眼/头标注缺口。[原论文](https://www.cv-foundation.org/openaccess/content_cvpr_2015/papers/Horn_Building_a_Bird_2015_CVPR_paper.pdf)

优先从 [Cornell 发布入口](https://dl.allaboutbirds.org/nabirds) 获取原始版。当前入口存在，但本轮未验证完整归档可直接下载；不同镜像可能为缩图/删图版，不能以文件同名代替身份核验。若原始获取受阻，先用第一批做实验并明确缺项，不静默换镜像。NABirds 同样要补充框语义，完成跨库去重；部位点自动圈出的 head proposal 只能作待人工修正的候选。

第一版不加入 Birdsnap/iNaturalist 全量，也不选择来源不明的网络“鸟眼 YOLO 标签包”。先把身体、头、眼和负样本的标注闭合，减少来源混杂。

### 4.4 独立实拍测试池

另预留 **不少于 20 段不同场景短片、约 1,000 个抽样人工标注帧** 为域外验收目标（尚未收集）。覆盖本地常见鸟、树枝遮挡、逆光、弱光、转头、飞行、多鸟、只露头及无鸟片段。

以拍摄日期/场次/连续序列/个体作分组，整组划分。不能把同一连拍相邻帧放到训练与测试。初版可只把它用于测试；公开数据上提升但实拍下降时，两类结果分别报告。没有这部分输入时，只能完成公开静态图评估，不能报告连续锁定实测。

### 4.5 首版精标子集规模

以下为目标配额，需在下载、去重、可见性检查后形成实际清单，不是已存在计数。

| split | 有鸟、完整三类标注 | 经检查无鸟 | 正例来源建议 |
|---|---:|---:|---|
| train | 4,000 | 2,000 | CUB 官方 train 池 3,000 + COCO train 池 1,000 |
| val | 1,000 | 500 | CUB train 池中独立 800 + COCO train 池中独立 200 |
| public_test | 1,500 | 1,000 | CUB 官方 test 池 1,000 + COCO val 池 500 |

总计 **10,000 张精标图**；其中 6,500 张有鸟需要补齐眼/头框。抽样按目标尺寸、可见性、姿态、背景分层，不能只挑正面大鸟。若首次精标成本过高，可以先做 300 张标注试点确认规范，再分批扩到目标；不能把未补标的图算作“完整精标”。实拍测试池另算。

跨 CUB/COCO/NABirds/实拍统一做文件哈希、近重复图检查和人工复核。同源或近重复组锁在同一 split；涉及官方 train/test 跨界的重复，优先隔离而不是把官方 test 放回训练。

## 5. 标注规范

统一 canonical 类别：`0=bird_body, 1=bird_head, 2=bird_eye`。物种、左右眼、姿态不是这三个类别的新标签，而是实例属性或 native 子类映射所需补充信息。

- 身体框：记录整鸟可见外形范围；截断/遮挡另记属性，不凭空推测不可见躯干大小。原数据身体框语义需检查，不能不经核对与新规范混合。
- 头框：明确围住头颅、脸/眼区域，鸟喙和颈部边界按统一手册执行；初稿可用关键点提出候选，必须修正。
- 眼框：围住可辨识眼部区域，另存人工眼中心。一个可见眼一个实例；不可见的远侧眼不补虚构坐标。闭眼、反光、模糊、遮挡分别标属性。
- 每个部位记录所属 `bird_instance_id`。多鸟必须标注全部可见个体，避免邻鸟的眼与当前鸟的头被错误组合。
- 每个部位的可用性保存三态：**可锁 / 不可锁 / 不确定**；不确定项的相应监督/指标忽略，不能等同于不存在。
- 另外检查实际 **384×256** 输入是否仍能辨识眼中心。保留原图可见性与输入可分辨性两个字段；眼在原图可见而缩小后消失的案例单列，不隐去整体眼召回。
- 测试/验证标注由人工确定；教师框不能作为最终真值。精标测试集做第二人复核或隔时复核及争议记录。

头/眼从点自动推框可用于提速；**不能只用固定半径给所有眼画小方框，再据此声称眼部精度**。

## 6. 共享的锁眼→锁头→锁身规则

先选定一个鸟个体，再在这个个体内选择部位：

1. 本个体有达到质量阈值的可用眼候选：选眼中心。
2. 无有效眼但有头候选：选头框中心。
3. 无有效头但有身体候选：选身体框中心。
4. 均无有效候选：输出 lost，不输出背景中心。

两个眼均可用时，选择校准质量分更高者；分数相同按固定规则打破平局。候选关联使用实例几何与短时关联，不从另一只鸟借眼。只露头时允许建立头部实例，不强制先检测到完整身体才允许锁眼。

初次自动选鸟采用同一明确规则，例如优先画面中心邻近的有效鸟实例，随后保持同一个体；同时报告“给定目标鸟”的单体诊断指标和自动选鸟的整体结果。不能把 GT 指定目标条件下的表现冒充全自动多鸟选择能力。

同一份选择器应用于 A/B/C；它是拟实施的研究逻辑，**没有宣称已证明等同尼康机内状态机**。A 的权重和 IPU 解码器仍保持不动，只将其输出经已确认的类别适配器送进共同选择器。

不同模型的分数不可直接共用 0.5 阈值。仅用 val 为每组校准部位门槛，在同样误锁/误报目标下比较召回，并给完整曲线；分数校准不改 A 的原模型。测试集不调门槛。

第一版静态结果逐帧按该规则输出，不靠额外跟踪器掩盖检测差异。视频先共用相同个体关联，统计丢失、错误切鸟和层级切换；时间平滑/滞回如新增，必须作为共享配置单独报告。

## 7. 训练与蒸馏配方（拟定起点）

### 教师

- 初始化：`yolo26m.pt`，检测头重建为三类。
- 输入：768×512，完整画面；若高分辨率输入显示有必要再开后续独立实验，不临时改主榜。
- 本地 AMP，小微批次 1–2 起测，梯度累积到有效 batch 16；先短测显存、梯度、标签，出现不支持/数值问题停止检查，不自动换结构或 GPU。
- 正式训练上限先定 100 epochs，只按 val 指标选 checkpoint。教师要同时看眼中心误差、头/身检测、负例误锁，不能只按身体 mAP 选。

### B/C 学生

- 输入均 384×256，有效 batch 均 16，训练样本顺序、每 epoch 抽样和增强随机种子匹配。
- B 从原 744 权重开始，C 从 YOLO26n 预训练权重开始；这本身是不同初始化，结论限定为实际方案比较。
- 两者最多 100 epochs、相同样本曝光次数。第一轮 seed=42；若链路和数据通过，再追加另外两个预先固定种子作稳定性复核。
- 原生图先建可微训练实现，必须与冻结执行器对照。原 IPU 的有界解释器不是自动求导后端；损失/坐标解码应经过数值检查，不能简单套错一版 YOLO loss。
- 第一版不做异构逐层特征蒸馏、不生硬对齐原生六类 raw logits 与 YOLO 三类 logits。使用匹配后的类别组、解码框/中心和教师质量监督；有 native 姿态子类时先恢复合法映射。
- 损失采用 `L_GT + λ_KD × (L_box_KD + L_part_KD + L_center_KD)`，各分量按匹配数量归一化。λ_KD 前 10 epochs 从 0 线性升到 1；仅在 train 上取教师结果。具体回归损失和 native 原始坐标变换在接口校验时冻结。
- 正式比较前给 B/C 相同小规模调参预算，例如最多 3 个学习率配置；不得只精调其中一组。报告实际优化器、学习率和训练 GPU 时间，不能把不同结构/初始化的差异归因于单一机制。
- 首版禁用 Mosaic/MixUp；翻转、裁剪、缩放时同步变换框、眼中心和可见性，裁掉/遮住的部位重新标有效性。离线缓存不能在做几何增强后原坐标照搬。
- 训练时允许 AMP，但主精度评测先固定 FP32；FP16 存储/推理结果作为部署相关的独立精度检查。原硬件舍入未被机身逐位验证。

教师错误与人工 GT 冲突时，优先人工 GT；教师未检出不代表图中无眼。没有可靠监督的部位不强行蒸馏为负例。

## 8. 精度评测：重点是最终选到哪里

| 指标 | 定义及用途 |
|---|---|
| 眼/头/身体 AP50、AP50:95 与召回 | 分开报告，不用一个鸟身体 mAP 代表锁眼 |
| 眼中心定位 | 输出中心到人工眼中心的像素误差，以及按头框对角线归一化误差；给 PCK@0.025/0.05/0.10 和 1/2/4 像素命中曲线 |
| 正确层级锁定率 | 眼可锁样本应锁正确眼；眼不可锁但头可锁应锁头；头眼均不可锁而身体可锁才应锁身；不确定状态单列 |
| 错误锁眼率 | 眼不可用时仍输出眼，或锁到其他个体/背景，分别计数 |
| 提前降级率 | 有可用眼却锁头/身；有可用头却只锁身，区分“保守但可用”与真正达到目标 |
| 无鸟误锁 | 每张负例的错误锁定比例/次数；用同一 operating point 比较，不凭低阈值的高召回获胜 |
| 视频 | 个体切换、丢失帧占比、头/身回退、恢复到眼的帧数和毫秒、锁点抖动；按 clip 汇总 |

头/身的命中同时报告所选点是否在对应 GT 框内和归一化中心误差；大框内任意点“命中”不能冒充精确中心定位。

按眼在 384×256 上的大小、鸟大小、遮挡、模糊、逆光、单/多鸟分别列结果。主表的总体结果保留所有样本，再给可分辨子集诊断；不能只挑清晰大鸟。

统计差值尽量在同一图片配对；视频按整个 clip 分组做区间估计，避免相邻帧被当成独立样本。无 GT/无视频的格子标缺失，不填写推断结果。此阶段测的是离线定位与锁点逻辑，不是镜头实际合焦率。

## 9. 运行时间评测：排除执行器差异

**禁止直接把 A 的 NumPy+BA2 解释器毫秒，与 C 的 CUDA/TensorRT 毫秒放一张“模型速度”榜。**

采用三层记录：

1. **共同计算后端的网络计时**：A 原权重、B 新权重、C 均有经验证的 PyTorch GPU 前向实现，batch=1，eval/no_grad、同设备、同输入、同 FP32。CUDA 同步或 events 正确计时，先预热 100 次，再至少 1,000 次记录 p50/p95/p99、均值和显存峰值。A 张量实现先对照现有 FP32 图及原输出，误差阈值按层/输出和候选分歧冻结；达不到时停止公平速度比较。
2. **完整可运行管线计时**：拆分图像解码、预处理、传输、网络、各自必要解码/NMS、共同选择器和总时间。原后处理可以用原解释器作正确性参照，但其解释开销独列。若做高效端口，需先对照通过；不能隐去 C 的必要后处理或把 A 的研究解释成本算成硬件成本。
3. **机身预算**：记录参数、MAC、支持算子、编译包、activation/workspace/访存估计；在真实调度/硬件执行尚未打通时，相机 ms/Hz 填“未测”。本地 GPU 快不能证明 Z8 可移植。

同一轮实验固定电源/性能模式，记录 GPU/驱动、温度和频率区间，避免其他 GPU 任务；按 A/B/C 交错顺序重复测量减少热状态偏差。不能将 batch>1 吞吐 FPS 当成单帧延迟。FP16、TensorRT、CPU 等如测试，另外成表，并保证各组实际支持和精度损失可比。

C 的三类头参数/MAC 应在实现后重新统计；此前按 80 类公开表粗估的约 0.66 GMAC 不是此版本的最终测量。

## 10. 进入实施前的顺序

1. 恢复并核对原生六类到三层任务的映射，冻结 A 身份和类别适配器。
2. 下载第一批原始数据及 m/n 权重，建立来源/哈希/许可/条目清单；隔离重复图，冻结 split。
3. 做 300 张精标试点，明确可锁眼和完整实例标注，复核后扩到目标子集。
4. 建立原结构可微实现与计时基线；原权重前向对照通过，固定图 PCNNP 原样重编码通过后，B 才具备进一步部署研究基础。
5. 用人工 GT 训练教师，在 val 验证后冻结；不看测试集来选教师。
6. 给 B/C 相同离线教师监督和训练/调参预算，训练后测试三主组。
7. 公开数据、实拍序列、运行成本分别判读；如要归因蒸馏，增加 KD=0 消融。
