# 较好图片与去重队列

本目录有三份用于挑选和对比的清单，都由脚本生成、可离线复核：

| 文件 | 内容 |
|---|---|
| [best-images-v1.json](../curation/best-images-v1.json) | 从确认样本里按可解释规则排出的 120 张优先查看清单 |
| [dedupe-queue-v1.json](../curation/dedupe-queue-v1.json) | 去重后的队列：694 张折叠 158 张，队列 536 张，42 组 |
| [labels/community-corrections-v1.jsonl](../labels/community-corrections-v1.jsonl) | 全部 694 条逐图标签 |

## 较好图片怎么选出来的

只从**人工确认、且在去重队列内**的图里选，规则写死在
`scripts/publish/export_best_images.py`：

```text
score = 4×覆盖度 + (3×删除框数 + 2×新增框数 + 修改框数) + (原厂零候选时 +2)
覆盖度 = 有眼 +2，有头 +1，有鸟 +1
```

结果：533 张合格，取前 120 张。分数分布：50 分段 1 张、40 分段 1 张、30 分段 26 张、20 分段 92 张。

| 划分 | 入选 |
|---|---:|
| train | 92 |
| val | 11 |
| test | 17 |

被排除的：147 张未确认或待裁决、12 张已折叠出队列、2 张没有任何鸟/头/眼物品。

**这个分数只表示"复核价值"和"纠错工作量"，不是识别准确率。** 分数高的图往往正是原厂框错得多的图，
拿它当"原厂表现好"的样张会读反。

## 图片在哪里

仓库不放照片。用 `image_id` 去 [registry.csv](../../registry.csv) 查到所属批次，再从对应 Release
下载：`community-images-2026-10-24-v1` … `community-images-2026-10-25-v5`。

## 去重队列

| 项 | 数量 |
|---|---:|
| 全部图片 | 694 |
| 折叠出队列 | 158 |
| 队列 | 536 |
| 折叠组 | 42 |
| 候选相似组（未折叠） | 101 |
| 被折叠的确认图 | 12 |

最大一组 6 张；其中 12 组的代表图不在 535 张跳过的确认集合里（属于草稿图的相似关系），
因此这些组没有划分归属。

关键事实：

- **158 张没有一张与根图像素完全相同**（输入 CHW 哈希 0 重合）。它们是同一场景/连拍的相似帧，不是字节重复。
- 折叠加了"每个成员必须与代表图直接匹配"的限制，不做传递压缩，避免整组被压成一张。
- 分组不跨训练/验证/测试划分（0 处冲突）。
- 折叠只影响队列视图，不改图片、不改标注、不改修订历史。

## 复核方式

```bash
python scripts/tools/verify_annotations.py
python -m unittest tests.test_published_exports -v
```

两份清单的 sha256 分别记录在各自 JSON 的 `digest` 字段与生成脚本输出中。
