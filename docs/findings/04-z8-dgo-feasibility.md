# Z8 DGO / Dual ISO 可行性评估

评估日期：2026-10-22。范围：本地两个项目的说明、核心补丁源码、传感器输入与追踪代码、两份固件的容器及字节差异，以及公开的一手技术资料。本轮没有运行相机或 QEMU，没有修改两份固件及两个项目的源文件。

后续针对 IMX609AQJ 的公开资料检索，见 [IMX609 DGO 支持证据补充](IMX609_DGO_research.md)。检索确认了 Z9 芯片身份及双数据流用途，但未取得同曝光双增益模式或寄存器证据。

## 结论

**存在值得验证的研究路线，但当前资料不足以认定 Z8 能通过固件实现同次曝光 DGO。最关键的缺口是传感器实际支持什么读出模式，而不是菜单、NEF 保存或合成算法。**

| 目标 | 当前判断 | 决定性条件 |
| --- | --- | --- |
| 同次曝光、每个像素获得高低增益读数后融合 | 尚无实现证据；不能作为已经可以开发的功能承诺 | 芯片支持保留同一曝光的信号并产生两次有效模拟域采样，或在片内完成等效融合；驱动能配置和接收 |
| Magic Lantern 类行对交错 Dual ISO | 可以作为优先调查的单帧路线；Z8 硬件能力尚未证明 | 可以独立配置行组的增益；若追求跨越 ISO 500 附近的低噪声优势，还必须支持相应工作区间的行组控制 |
| 相邻帧高低 ISO / 不同曝光合成 | 原理与现有拍摄接口支持，最容易做原型 | 帧配对、参数生效时刻、配准与运动处理；属于多次曝光 |
| 单份普通 RAW 复制后提亮、改 ISO 标签或修改 Log/LUT | 不能产生新的采集动态范围 | 没有第二份具有不同模拟域噪声/饱和特性的观测 |

不为尚未识别的硬件能力编造成功率。没有找到一个模式，不等于已经证明芯片绝对不支持该模式。

## 2. 源码证明了什么

### 补丁基础可复用，但传感器模式还没有被解锁

`NikonFirmwarePatch/features.py:7` 的功能集合只有 `prores` 和 `precapture`。`z8precapture/firmware.c` 主要处理已有帧资源、HE/HE★ 编码预算、NEF 封装、原生写文件接口、预览和双卡路由。它没有实现两套成像增益的配置与采样。

这套工程已提供有价值的固件容器、代码注入、菜单和图像保存基础。项目文档还记录了现有功能的相机文件验证；这属于原作者的验证记录，不能外推成 DGO 验证，也不是本轮重新完成的实机测试。

### QEMU 可以检查固件流程，不能判定真实传感器的隐藏功能

- `z8-qemu/tools/make_cmos.py` 生成合成 RGGB 色条。
- `qemu/nikon-z8-raw-pixels.h:13` 的输入结构保存一套样本数组；它没有给出同次曝光高低增益双观测的物理模型。
- `qemu/nikon-z8-d980.h:3` 明确说明打包及重采样属于实验假设，原生格式/stride 数值不能证明物理线格式或实际传感器精度。
- `tools/rom_inputs.py` 使用合成外部 ROM 数据，并明确标记不是恢复出的出厂校准参数。
- `tools/service_serial8.py:37` 明确记录外设身份未知、协议接受未确认、数据不是像素。串行通道编号本身不能被当作已识别的传感器增益接口。
- `tools/model-properties.json:71` 明确限定为功能性 ISP，而非物理传感器行为。

因此，在 QEMU 中添加两份合成 RAW 并成功保存，只能验证软件数据通路；真实 Z8 能否产生这两份观测仍需独立证据。代码中的双 buffer、双 bank、双 ISP 路径，也不能单凭数量被认定为双增益通道。

### 固件字符串只是下一步导航线索

对解包后的五个模块做了静态 ASCII 字符串初筛。值得进一步追踪的主载荷偏移包括：

| 偏移 | 内容 | 目前可作的解释 |
| --- | --- | --- |
| `0x4ccb5e4` | `CaptureSensorSer` | 存在传感器相关服务名称；没有因此识别出其入口或增益寄存器 |
| `0x15bce30` | `HdrComposition.cpp` | 存在 HDR 合成相关代码/符号线索；尚未恢复调用链 |
| `0x15c072d` / `0x15c4ed3` | `HdrComposition420` / `HdrComposition422` 的修饰名称 | 可能涉及图像域合成；不是双模拟读出的证明 |
| `0x401ab7f` / `0x401ab95` | `eDSID_Setting_HdrMode` / `eDSID_Setting_HdrBeforeOverlayRawSave` | 与现有 HDR 设置一致的名称线索 |

初筛还会命中代码随机字节、PNG/文件头中的 hdr 和普通调色 Gain 名称，不能按命中次数判断功能。没有定位到具有已确认语义的 DGO/DCG 模式开关或行组增益表。没有对整份固件完成反汇编、调用图和寄存器语义恢复。

`z8precapture/firmware.c` 中的 `HDR_MAX` 实际是 NEF **header** 大小上限，不能解释为 HDR 模式。

## 3. 必须区分的三种采集方式

### 同次曝光 DGO

要求同一像素、同一次积分曝光的信息，在不同模拟增益下形成有效观测，然后融合。读出可以并行，也可以时分，不能把“需要两套独立 ADC”当作必然条件。佳能白皮书给出的实现就包含信号存储、同步增益切换和时分读出。

软件不能为不具备这种能力的芯片补出模拟采样与信号保留机制；如果硬件已经具备但驱动未使用，才有固件解锁的空间。成像数据也可能先在传感器片内融合，因此“没有在内存中看到两帧”并不能单独否定 DGO。

来源：[Canon DGO 白皮书，第 4-5 页](https://downloads.canon.com/cinemaeos/DGO-Sensor-White-Paper.pdf)、[Canon 官方技术说明](https://www.canon-europe.com/pro/stories/dgo-sensor-explained/)。

### 行对交错 Dual ISO

Magic Lantern 的做法按行对交替使用两个 ISO；不同增益分别获得空间上不同的样本，不是每个像素都有两份读数。其项目说明明确列出垂直分辨率、混叠和摩尔纹代价。Z8 的 Bayer 行组安排必须保证两套增益都有所需的颜色采样，不能直接移植佳能寄存器或数值。

尤其要确认 Z8 是否允许行组独立进入 ISO 500 附近的低噪声区间。若转换增益等关键模式只能整帧切换，仅找到两个普通模拟放大量字段，未必能复制这一区间的噪声收益。

来源：[Magic Lantern Dual ISO 项目说明](https://raw.githubusercontent.com/reticulatedpines/magiclantern_simplified/dev/modules/dual_iso/README.rst)、[实现源码](https://github.com/reticulatedpines/magiclantern_simplified/blob/dev/modules/dual_iso/dual_iso.c)。

### 跨帧 HDR / ISO 包围

这是现成的验证替代路径。Nikon 官方 HDR Overlay 明确说明由两次不同曝光合成，且可以保存组成 HDR 的独立 NEF；M 档包围也可设置变化 ISO。它可以用来研究融合质量，但会有帧间时间差，运动、闪光或频闪可能造成不一致。帧间 ISO 变化是否能按自定义 C15/C30 节奏稳定生效，仍需另行测试。

来源：[Nikon Z8 HDR Overlay](https://onlinemanual.nikonimglib.com/z8/en/psm_hdr_overlay_152.html)、[Nikon Z8 Bracketing](https://onlinemanual.nikonimglib.com/z8/en/bracketing_36.html)。

## 4. 如果硬件支持，潜在收益是否有意义

有意义，但不能用 ISO 倍数直接当作动态范围收益。

从测量发布者 Photons to Photos 的 Z8 14-bit 静态照片读噪曲线提取的数据为：

| 标称 ISO 附近 | 图表 log2(electrons) | 换算输入等效读噪 |
| --- | ---: | ---: |
| 64 | 2.81 | 约 7.01 e− |
| 400 | 2.46 | 约 5.50 e− |
| 500 | 0.33 | 约 1.26 e− |

坐标经过源站舍入；64 和 500 对应源图 tooltip 约 63 和 503。这里将其对应为标准标称档位。详细源行、坐标换算、抓取时间和源页面哈希在 [public_noise_audit.json](public_noise_audit.json)，可用 `audit_public_noise.py` 重取。

来源：[Photons to Photos 原始测量曲线](https://photonstophotos.net/Charts/RN_e.htm#Nikon%20Z%208_14)。

如果某个模式确实能同时保留低 ISO 的高光上限与高 ISO 的低读噪，而且融合没有引入额外损失，那么读噪受限端的理想优势量级可估为：

```text
ΔDR ≈ log2(σ_low / σ_high)
    ≈ 2.81 − 0.33
    ≈ 2.48 EV
```

**这不是已经实现的 Z8 DGO 成绩，也不是严格上界。** 它是以两种独立普通模式的公开测量为条件的推算。新读出模式的噪声、量化、行模式重建、校准和合成误差会改变结果；没有本机重复样本、误差条或视频模式验证。

相比之下，64 到 400 的读噪差仅约 `2.81 − 2.46 = 0.35 EV`。这说明为什么必须查到正确的低噪声模式控制，不能只追求“两种 ISO 看起来亮度不同”。这些测量支持存在工作区间差异，不能单凭曲线确定具体寄存器或电路拓扑。

## 5. 工程瓶颈和复用边界

1. **传感器与驱动是首要瓶颈。** 需要识别增益设置的实际下发路径、模式寄存器、参数生效边界和复位/采样关系。没有公开可核对的 Z8 成像芯片完整寄存器手册或本机总线日志，不能以其他 Sony/Nikon 型号代替。
2. **带宽需要重新核算。** 以已有 8280×5520 RAW 缓冲尺寸算，两套完整 14-bit 样本约 160 MB/输出帧；20 fps 时样本预算约 3.2 GB/s，尚未计 stride、协议与额外读写。该数值不是测出的物理链路上限，也不适用于在传感器片内先融合的结构；它说明不能从现有单路拍摄性能直接推出同速双路可用。
3. **校准不能只乘一个 ISO 比值。** 黑电平、每色通道实际增益、饱和阈值、行列固定图样及融合接缝均需处理。仅提高整体亮度不能证明读噪降低。
4. **输出格式有独立工作量。** 当前 14-bit NEF 和 HE/HE★ 保存路径可供参考，但未经证明能直接容纳双增益融合后的有效精度。第一版可先分别导出原始样本，在电脑上融合并输出高精度 DNG；兼容普通 NEF 与机内预览留到后续。
5. **预拍摄代码不是直接的数据获取接口。** 它主要利用已有帧资源和编码结果；双增益获取/融合通常需要更靠前的采集或处理位置。不能直接把已经压缩的 E 资源当作两套独立线性 Bayer。

## 6. 建议的最小验证路线与停止条件

| 阶段 | 要完成的工作 | 通过证据 |
| --- | --- | --- |
| A：识别普通增益控制 | 固定照片模式、尺寸、快门与光圈，对比 ISO 64/400/500/640 的配置路径；追踪传感器服务及其实际下发接口 | 参数到总线/寄存器的对应关系及生效时刻；区分传感器模拟控制和后端数字增益 |
| B：验证硬件能力 | 查同次曝光双读出、片内融合或行组独立增益的模式；先用单张、低速路径验证 | 两套有区别的模拟观测，或经对照验证的融合输出；确认是否跨帧、是否同一积分时间 |
| C：测量真实收益 | 用暗场、均匀平场、灰阶/高光及细节图，在一致温度和处理条件下测读噪、饱和、线性、行纹与颜色 | 同时保留低增益高光范围和降低阴影噪声；行交错还需测分辨率、混叠与摩尔纹 |
| D：接入现有补丁 | 复用菜单、状态管理、保存和版本校验；随后再考虑连拍、预拍摄与视频 | 固件流程及实际 RAW 像素均通过验证；QEMU 检查流程，实机检查传感器行为 |

阶段 A 可以先在原厂 C3.11 路径进行只读追踪。QEMU 可以帮助找调用路径和日志，但无法补出未被模拟或未被采集到的硬件行为。`plugins/z8trace.c` 与 `tools/trace_plugin.py` 提供现成观测框架；需要先恢复准确地址，本报告没有提供未经验证的增益写入地址。

如果最后只确认了整帧增益切换，而没有同曝光双读出、片内融合或行组模式，那么当前证据就只支持跨帧方案。此时应调整目标，而不是继续修改菜单并把它命名为 DGO。

**投入建议：先把研究目标定为“识别 Z8 的增益控制并验证单帧双工作区间能力”。确认硬件条件后再开发完整功能。现有项目显著降低了外围固件工程成本，但尚未跨过最决定性的硬件门槛。**
