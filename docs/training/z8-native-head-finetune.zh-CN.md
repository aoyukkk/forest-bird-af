# Z8 原厂检测头微调：第二轮结果与权重发布边界

[English](z8-native-head-finetune.md) | **简体中文**

日期：2026-10-25。机器可读记录：
[z8-native-head-finetune.json](z8-native-head-finetune.json)。上一轮计划与
方法说明见 [本地原生检测头微调](z8-head-training.zh-CN.md)。

**结论：上一版实验候选在留出测试集上宏平均 F1 从 43.89% 升到 46.92%，眼命中从
4/22 升到 6/22，但眼精确率从 80.00% 掉到 66.67%。5,000 次组级 bootstrap 的
宏 F1 差值 95% 百分位区间是 [0.00, 4.90] 个百分点，触及零。这一版只算实验
候选，不推荐替换原厂模型，也不能当作机身对焦效果。**

第二轮继续微调了 4 组配置，没有任何一组在精确率约束下超过上一版父权重，
`selected_epoch = -1` 明确表示保留 `trial_005` 第 59 轮。

## 数据

从生产数据库只读快照取得 694 张已复核记录，排除 158 张去重隐藏图与 1 张待裁决图，
得到 535 张确认可用图片。

| 划分 | 图片 | 保守关联组 | 鸟 | 头 | 眼 |
|---|---:|---:|---:|---:|---:|
| 训练 | 375 | 56 | 385 | 301 | 174 |
| 验证 | 80 | 6 | 79 | 50 | 25 |
| 测试 | 80 | 5 | 83 | 59 | 22 |

划分在训练前冻结，测试集在验证集选型完成后才打开一次。发布的划分与标签在
`data/annotations-2026-10-25/`，可用 `python scripts/tools/verify_annotations.py` 离线校验。

两个必须一起读的限制：测试集 80 张里有 58 张属于同一个保守组，因此不是 80 个
独立场景；标签来自 Z8 辅助人工复核，不是独立盲标，坐标绑定冻结的 384×256 输入。

## 方法

- 原厂骨干冻结，训练前 535 张图的缓存特征全部通过冻结 FP16 输出逐位重放检查。
- 前向保留原生 dot/add/FP16 存储；反向用显式记录的 STE 近似梯度，不声称求出整数
  运算的真实导数。
- 只允许原检测头中 2,130 个参数更新，选中权重实际变化 1,350 个 FP16 参数，
  允许范围外变化为 0。
- 后处理仍用原厂消费者，阈值与查表未改。
- 选型只看验证集宏 F1，并约束每部位召回下降不超过 0.05、F1 下降不超过 0.03；
  F1 约束在第 4 组之后就地在验证集追加，测试集尚未打开。

## 结果

严格判据：鸟、头 IoU≥0.5，眼中心距≤4 个输入像素，一对一计数；未标部位不作为
硬负例。

| 指标 | 原模型 | 候选 |
|---|---:|---:|
| 鸟身 F1 | 47.33% | 47.33% |
| 鸟头 F1 | 54.72% | 54.72% |
| 眼 F1 | 29.63% | 38.71% |
| **宏平均 F1** | **43.89%** | **46.92%** |
| 鸟身命中 / 标签 | 31 / 83 | 31 / 83 |
| 鸟头命中 / 标签 | 29 / 59 | 29 / 59 |
| 眼命中 / 标签 | 4 / 22 | 6 / 22 |
| 眼部未匹配位置误检 | 1 | 3 |
| 眼精确率 | 80.00% | 66.67% |
| 眼召回率 | 18.18% | 27.27% |

放宽判据（IoU≥0.3、眼距≤8 像素）下宏 F1 由 45.15% 升到 48.18%，结论方向一致。

多找到两个眼，也新增两个未匹配位置的眼候选。鸟身、鸟头统计在测试集上没有退化，
但这只是 5 个保守组上的结果，不能外推。

## 权重和标注为何不直接上传

- **候选权重不入库。** `resource744.finetuned.body.bin` 里绝大部分字节仍是厂商数值参数，
  变化的 2,248 字节叠加在厂商权重之上。公开它等于公开原厂权重，因此只公开哈希、
  字节差异范围和复现方法。
- **原片与公开副本不入库。** 图片通过 Releases 分发，仓库只放清单、哈希和标签。
- **数据库不入库。** 生产标注库、去重记录和逐次执行快照留在仓库外；公开的是经过字段
  瘦身的标签文件，原图绝对路径、原资产哈希、参考图哈希和复核者标识都已剔除。

权重身份可以核对：原厂 body SHA-256
`e8d371e77efc3035d0c633c8c90aa4851f1675e5abcf7999edb23adc6439722b`，
候选 body SHA-256
`7171a42d8e9148ba9dd534f5096914818715ad414fed74a60964406cba781a0a`。

## 复现

```bash
python scripts/training/prepare_z8_training.py --help   # 冻结划分与特征缓存（需要本机原厂包）
python scripts/training/train_z8_heads.py --help        # 训练与导出候选 body
python scripts/training/evaluate_z8_training.py --help  # 打开测试集的单次评估
python scripts/publish/export_z8_labels.py --help      # 生产库 → 可发布标签
python scripts/publish/export_split_manifest.py --help # 冻结划分 → 可发布清单
python scripts/tools/verify_annotations.py           # 离线校验标签与划分
```

前三个脚本需要本机已校验的原厂模型包和 CUDA，仓库不含这些依赖；后三个脚本只依赖
标准库，可直接对已发布文件复核。

## 下一步

- 眼候选的主要问题是未匹配位置的误检：5 个验证误检距人工眼点 8.09–11.19 像素，
  且全部落在当前背景保护半径内，现有背景负监督覆盖不到。
- 还需要更多独立复核的眼负样本；目前可恢复到原生位置的人工删除眼误检只有 4 个。
- 先扩大独立保守组数量，再讨论留出收益。
- 相位测距、镜头驱动和整机 AF 闭环不在本轮范围内，任何配对焦率都不成立。
