# 林鸟首轮执行：标注、Z8 基线及 Sony 运行准入

本记录继承冻结的 run_001。20 张独立 AI 标注草稿及 Z8 试跑已完成；Sony 图片推理仍为 0 张，200 张成对比较尚未开始。没有训练、蒸馏、微调或 GPU 运算。后续只在服务器私有临时目录使用 Linux CPU 模拟库进行运行准入检查。

## 可交付的标注与 Z8 结果

- 独立标注包：`../run_001/pilot20_blind_annotation.zip`。含 20 张原图、空 JSONL 模板及规范，不含我们的草稿或相机模型答案，可直接交给其他模型。
- 并排复核页：`../run_001/pilot_review.html`。逐图展示原图、独立 AI 草稿和 Z8 数字类号输出。
- 草稿：`../run_001/pilot20/blind_ai_draft/annotations.jsonl`。20 张都有整鸟/头部草稿，13 张记录了可定位眼中心；全部需要人工复核，尚不能作为计分真值或训练标签。
- Z8 744：20/20 执行成功、0 错误、共 74 条候选。两个样本重复运行时输入、FP16 输出字节和原生后处理包一致。这验证本次软件运行的可重复性，尚未证明与机身硬件逐位等价。
- 主机观测中位数：CNN forward 107.7 ms，CNN 加原后处理 452.6 ms，含读写与序列化 487.07 ms。这是当前 CPU 重建路径耗时，不能推算机身 AF 频率或 A800 推理性能。

74 条候选不是 74 次正确检测；20 张都有候选不是召回率 100%。Z8 类号 0～5 的固件消费者语义尚未确认，因此目前不报告眼/头/鸟准确率。样本为定向诊断选样，也不能外推总体准确率。

标注继续采用整鸟可见框、头部可见框、可定位眼中心（眼框可选），记录部位可见性及遮挡原因，保持实例关联。不要补画被遮挡眼睛，不要求额外逐一标翅膀、尾、脚。先独立标注，再与两套输出核对；不能只检查模型意见不同的图片，因为两边也可能共同出错。后续训练可侧重已人工确认的困难/错误样本，并保留正常场景回归样本与独立留出集。

## Sony 格式修正：可解析容器不等于可推理

已用 VeriSilicon 官方 MIT 许可的 NBG 解析器源码编译本机 C 程序，并对 7 个原文件实际调用；官方源码及 SDK 固定到提交 `702715d714277376d7ff466b7b72833ff57564c1`，下载的 59 文件逐个核对 Git blob SHA-1 及 SHA-256。

| 资产 | 元数据解析 | 已确认内容 |
|---|---|---|
| 08 / 09 / 10 / 13 / 14 | 5/5 成功 | Vivante VIPLite NBG，版本 0x0001000f，CID 0xd4；1 输入、21 输出；输入 UINT8、affine asymmetric、zero_point=128、scale≈2/255；原始维度 [320,320,3,1] |
| 15 / 16 头部网络 | 解析器拒绝 | 原始文件版本字段 0x00010016；当前官方源码解析器最大支持 0x00010014。未用修改版本号绕过检查 |

旧提取报告中“INT8、zero_point=-127”的判断需要撤回：-127 位于 fixed_pos 字段，在上述非对称量化设置下不是零点。不能从文件名、42 通道或命名记录数单独确定 YOLO 解码、类别、布局及网络消费者。以上输入量化结论仅适用于解析成功的 5 个资产；还不能据此确定 RGB/BGR、裁剪缩放和归一化的完整链路。

旧报告及 run_001 保持不动，本报告为后续修正。详见 `vendor_parser_results/summary.json` 和逐模型原始 stdout/stderr。

## Linux CPU 模拟库的实测结果

服务器：`klz@10.184.27.20:22`；专用目录 `/tmp/klz_z8_af_20261023_run002/payload`。使用官方 x86_64 SDK 的 OpenVX、Emulator 和 ArchModelSw 库；设置 CUDA_VISIBLE_DEVICES 为空，未运行训练或 GPU 作业。库依赖检查、编译和失败输出均已保存。

1. 初次测试：上下文创建成功；SDK 仓库自带 `conv2d_relu_maxpool2d_fp32.nbg` 导入返回空 kernel，退出码 5。样例自身版本为 0x0001001e，高于随仓库解析器的范围；这提示版本不配套，但尚不能仅凭该差异断言原生导入失败的根因。控制样例失败后没有继续导入 Sony。
2. 在 `amendment_002.json` 中记录调整，保留原失败，使用同一 SDK 构建 FP32 小型加法控制网络。创建、验图、计算、读取输出均返回成功；16 个输出与预期逐项数值一致。
3. 同一控制程序随后在 NBG 导出阶段收到 SIGSEGV（退出 -11）。保持同一二进制，仅关闭 stdout 缓冲后复查，确认日志最后为 `NUMERIC_PASS_16_VALUES`，尚未打印 `NBG_SIZE` 返回值。因此模型导出—重新导入自检未通过，Sony 导入及图片推理仍未执行。
4. 一次 gdb 诊断达到 45 秒上限，未取得调用栈；已保存超时记录。随后检查该私有控制程序无残留进程。不能把尚未定位的崩溃直接归因于 Sony 模型或硬件 CID 不兼容，也不能排除本封装/API 使用及 SDK 配置问题。

所有 Sony 文件保持原始字节，没有改 CID、版本号、量化参数，没有切换其他推理后端来制造“已跑通”结果。实测记录在 `remote_probe_results/` 与 `remote_probe_results_v2/`。
